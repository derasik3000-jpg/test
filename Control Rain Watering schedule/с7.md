## **1\) Основная идея (Apple Human Interface Guidelines+ 2025\)**

### **1.1 Проблема и инсайт (Apple Human Interface Guidelines+ 2025\)**

* **Apple Human Interface Guidelines+ 2025:** На фермах с поливом (капля, дождевание) реальность такая: поливы происходят часто, быстро, в разных участках, и фиксируются “как получится” — в блокноте, в мессенджере, в голове, на бумаге. Итог — нет единой картины: *когда, где, сколько, почему*.  
* **Apple Human Interface Guidelines+ 2025:** Ошибки и потери денег возникают не из\-за “нехватки функций”, а из\-за отсутствия **простого, повторяемого ритуала**: *запланировал → сделал → зафиксировал → проверил состояние почвы/растений → сравнил недели*.  
* **Apple Human Interface Guidelines+ 2025:** Ключевая боль — **не скорость ввода**, а **контекст и доказательства**. Если полив не привязан к участку, длительности и состоянию почвы (фото/оценка), то журнал превращается в шум и не помогает принимать решения.  
* **Apple Human Interface Guidelines+ 2025:** Инсайт: пользователю нужен “карманный поливной журнал”, который работает как **инструмент на поле**: крупные действия, минимум шагов, понятные состояния, офлайн-first, и визуальная сводка “по неделям”. Это должно ощущаться нативно и предсказуемо по Apple Human Interface Guidelines+ 2025 (принципы ясности и лучших практик интерфейса). ([Apple Developer](https://developer.apple.com/design/human-interface-guidelines?utm_source=chatgpt.com))  
* **Apple Human Interface Guidelines+ 2025:** “Погодные условия” в рамках ограничений (без внешних API/сервисов) делаем **инструментально и честно**: не “прогноз”, а **правила напоминаний, основанные на данных пользователя** (например, “если не было дождя X дней по ручным отметкам/осадкам”, “если почва отмечена как сухая два осмотра подряд”, “если плановый полив пропущен”). Это делает продукт полезным без интеграций.

### **1.2 Ключевые сценарии (JTBD) (Apple Human Interface Guidelines+ 2025\)**

1. **Apple Human Interface Guidelines+ 2025 — JTBD: “Записать полив за 10 секунд”**  
   Когда я только что полил участок, я хочу одним быстрым действием выбрать участок, длительность и добавить короткий комментарий, чтобы журнал был точным без лишних форм.  
2. **Apple Human Interface Guidelines+ 2025 — JTBD: “Видеть календарь поливов по участкам”**  
   Когда я планирую неделю, я хочу открыть календарь и увидеть, где и когда были/будут поливы, чтобы держать режим и не забывать участки.  
3. **Apple Human Interface Guidelines+ 2025 — JTBD: “Получать напоминания по графику и условиям”**  
   Когда наступает время по шаблону или выполняется условие (например, давно не было дождя / почва сухая), я хочу получить понятное напоминание с быстрым действием “Записать полив”, чтобы не терять ритм.  
4. **Apple Human Interface Guidelines+ 2025 — JTBD: “Фиксировать состояние почвы/растений фото-доказательством”**  
   Когда я вижу сухость, корку, переувлажнение, стресс растений, я хочу быстро сделать фото и отметить состояние (шкала \+ заметка), чтобы потом сравнить “до/после” и понять эффект поливов.  
5. **Apple Human Interface Guidelines+ 2025 — JTBD: “Сводка по неделям: как часто поливали”**  
   Когда я подвожу итоги, я хочу увидеть частоту поливов по участкам и тренд по неделям, чтобы выявлять перекосы и стабилизировать режим.  
6. **Apple Human Interface Guidelines+ 2025 — JTBD: “Разобрать пропуски и причины”**  
   Когда полив не состоялся, я хочу отметить “пропуск” и причину (ремонт, дождь, нехватка воды), чтобы календарь был честным и аналитика не искажалась.  
7. **Apple Human Interface Guidelines+ 2025 — JTBD: “Быстро найти историю по участку”**  
   Когда спрашивают “когда последний раз поливали этот участок?”, я хочу открыть карточку участка и сразу увидеть последние поливы, фото состояния и заметки.

### **1.3 Радиус продукта (v1) (Apple Human Interface Guidelines+ 2025\)**

iPhone, iOS 15+, офлайн-first, без аккаунтов, без сторонних API/интеграций/сервисов, без локализации, без iPad.

**Модули v1 (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025 — Участки (Plots):** список участков с типом полива (капля/дождевание), базовыми параметрами (название, культура/зона, примечания), “быстрый статус недели”.  
* **Apple Human Interface Guidelines+ 2025 — Календарь поливов:** месяц/неделя/день, слои событий (факт/план/пропуск), фильтр по участку, быстрые действия.  
* **Apple Human Interface Guidelines+ 2025 — Быстрая фиксация полива:** участок \+ длительность \+ комментарий \+ (опционально) тип полива/интенсивность \+ “был ли дождь” (ручная отметка).  
* **Apple Human Interface Guidelines+ 2025 — Состояние почвы/растений:** фото \+ шкала состояния \+ метки (сухо/норма/влажно/перелив/стресс) \+ заметка \+ привязка к участку и дате.  
* **Apple Human Interface Guidelines+ 2025 — Шаблоны графиков:** “каждые N дней”, “в определённые дни недели”, “по фазе” (упрощённо: пользовательские пресеты), применимые к выбранным участкам.  
* **Apple Human Interface Guidelines+ 2025 — Напоминания (Local Notifications):**  
  * по расписанию (шаблоны)  
  * по условиям, проверяемым локально по данным приложения (например, “сухо 2 раза подряд”, “нет отметки дождя X дней”, “пропущен плановый полив”)  
  * с быстрым действием “Записать полив” / “Отложить” / “Отметить пропуск”.  
* **Apple Human Interface Guidelines+ 2025 — Недельные сводки:** частота поливов по участкам, “серии” (стрик), сравнение недель, заметки недели.  
* **Apple Human Interface Guidelines+ 2025 — Экспорт:** PDF/CSV отчёт по периоду (участок→поливы→фото состояния) через системный Share Sheet.  
* **Apple Human Interface Guidelines+ 2025 — Поиск и фильтры:** по участкам, событиям, тегам состояния, периоду.

**Что точно не входит в v1 (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025:** прогноз погоды/получение погоды извне (нет внешних API).  
* **Apple Human Interface Guidelines+ 2025:** аккаунты/облако/синхронизация.  
* **Apple Human Interface Guidelines+ 2025:** датчики/интеграции с контроллерами полива.

### **1.4 Продуктовые принципы UX (HIG-совместимые) (Apple Human Interface Guidelines+ 2025\)**

* **Apple Human Interface Guidelines+ 2025:** Предсказуемая навигация iOS: Tab Bar для разделов, Navigation Stack внутри, модальные листы для создания/редактирования. (Tab bars как основной способ навигации по разделам.) ([Apple Developer](https://developer.apple.com/design/human-interface-guidelines/tab-bars?utm_source=chatgpt.com))  
* **Apple Human Interface Guidelines+ 2025:** “Один главный шаг” на экране: на календаре — “Добавить полив”, на участке — “Записать полив”, на состоянии — “Сделать фото”. Остальное вторично и не шумит.  
* **Apple Human Interface Guidelines+ 2025:** Быстрый ввод без когнитивной нагрузки: значения по умолчанию, последние использованные участки, быстрые пресеты длительности (например 10/20/30/45/60), автосохранение.  
* **Apple Human Interface Guidelines+ 2025:** Контекст всегда рядом: событие полива и фото состояния связаны с участком и датой, а пользователь не “ищет по папкам”.  
* **Apple Human Interface Guidelines+ 2025:** Не полагаться только на цвет: факт/план/пропуск различаются не только тоном, но и формой бейджа, иконкой, подписью.  
* **Apple Human Interface Guidelines+ 2025:** Доступность и работа “на солнце”: крупные цели касания, высококонтрастные подписи, устойчивые пустые состояния (“Нет поливов — добавьте первый”).  
* **Apple Human Interface Guidelines+ 2025:** Анимации и 3D — функциональные: помогают считывать переходы (создание события, смена недели, подтверждение сохранения), а не отвлекают.  
* **Apple Human Interface Guidelines+ 2025:** Системные контролы там, где это уместно: выбор даты/времени через date picker (быстро и эффективно для выбора даты/времени). ([Apple Developer](https://developer.apple.com/design/human-interface-guidelines/pickers?utm_source=chatgpt.com))

## **2\) Дизайн и цветовая палитра (HIG-Aligned) (Apple Human Interface Guidelines+ 2025\)**

### **2.1 ДНК дизайна (2025) (Apple Human Interface Guidelines+ 2025\)**

**Позиционирование визуала (Apple Human Interface Guidelines+ 2025):** “Премиальный полевой журнал”. Он выглядит как современный iOS-инструмент 2025 года: уверенная типографика, слои/глубина, аккуратный motion, 3D-акценты на карточках и календаре.

**Композиция и слои (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025:** Золото — это “канва/атмосфера”, но основной контент всегда на “рабочих поверхностях” (серые карточки), чтобы сохранять читаемость и спокойствие.  
* **Apple Human Interface Guidelines+ 2025:** Карточная система: “Участок”, “Событие полива”, “Состояние почвы” — все карточки одного семейства (радиус, тени, отступы), чтобы интерфейс был цельным.  
* **Apple Human Interface Guidelines+ 2025:** Чёрный — только для первичных действий и ключевых акцентов (CTA), чтобы пользователь всегда понимал “что главное”.

**3D и Motion (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025:** Календарь как “объёмный слой”: неделя/день переключаются плавным spring-сдвигом, карточки событий имеют лёгкий 3D-lift при нажатии (неон/радуга запрещены).  
* **Apple Human Interface Guidelines+ 2025:** “Сохранено” показываем микро-анимацией статуса (например, чек/капля) \+ лёгкий haptic, чтобы действия ощущались надёжно и “живыми”.  
* **Apple Human Interface Guidelines+ 2025:** Фото состояния: переход миниатюра → просмотр делаем нативным “zoom”, без лишних эффектов; в просмотре есть сравнение “до/после” (когда снимки в разные даты).

**Иконографика и микрокопи (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025:** SF Symbols для статусов и типов (капля/дождевание/фото/календарь), единый стиль веса, без “разнобоя”.  
* **Apple Human Interface Guidelines+ 2025:** Тексты короткие и предметные: “Записать полив”, “Добавить фото”, “Отметить пропуск”, “Неделя: 4 полива”.

**Ключевые фирменные элементы (Apple Human Interface Guidelines+ 2025):**

* **Apple Human Interface Guidelines+ 2025 — Water Card:** карточка события полива с крупной длительностью, участком, маленькой подписью-комментарием, и “маркером типа” (капля/дождевание).  
* **Apple Human Interface Guidelines+ 2025 — Soil Snapshot Strip:** лента фото состояния участка по датам (таймлайн), где видно прогресс.  
* **Apple Human Interface Guidelines+ 2025 — Weekly Pulse:** недельный “пульс” частоты полива: компактная визуализация в карточке участка (сколько раз/серия/пропуски).

# **3\) Экраны (включительно экраны onboarding) и навигация (Apple Human Interface Guidelines+ 2025\)**

## **3.1 Навигационная модель (Apple Human Interface Guidelines+ 2025\)**

**Apple Human Interface Guidelines+ 2025:** используем нативный каркас:

* **Tab Bar** как глобальная навигация.  
* **Navigation Stack** внутри вкладок.  
* **Sheets** для создания/редактирования (быстрые формы).  
* **Full-screen** — только для просмотра фото/сравнения “до-после” и для режима “быстрой фиксации” (если нужно крупно, на поле).

### **3.1.1 Вкладки Tab Bar (Apple Human Interface Guidelines+ 2025\) — 4 вкладки**

1. **Календарь**  
2. **Участки**  
3. **Состояние**  
4. **Сводка**

**Почему так (Apple Human Interface Guidelines+ 2025):**

* “Календарь” — главный рабочий сценарий (план/факт).  
* “Участки” — быстрый доступ к карточке участка и истории.  
* “Состояние” — фото-дневник почвы/растений (восприятие эффекта полива).  
* “Сводка” — недельная аналитика “как часто поливали”.

Настройки/шаблоны/справочники — через **⚙︎** в правом верхнем углу на вкладке “Участки” или “Сводка” (а не отдельная вкладка), чтобы Tab Bar оставался компактным и предсказуемым по Apple Human Interface Guidelines+ 2025\.

## **3.2 Onboarding (первый запуск) (Apple Human Interface Guidelines+ 2025\)**

**Цель:** за 1–2 минуты довести до состояния “я могу вести журнал”, создав 1–3 участка и включив напоминания по шаблону (без погоды извне).

### **O0. First Launch Gate (Apple Human Interface Guidelines+ 2025\)**

* Условие: первый запуск или после “Сброс данных”.  
* Действие: показываем последовательный onboarding.

### **O1. Welcome (Apple Human Interface Guidelines+ 2025\)**

* Заголовок: “Журнал поливов и состояния почвы”  
* 3 коротких пункта:  
  * “Календарь поливов по участкам”  
  * “Фото состояния почвы и растений”  
  * “Недельная сводка частоты”  
* CTA (черная кнопка RAL 9005): “Начать”  
* Secondary: “Посмотреть демо” (мини-превью 3 карточек со свайпом)

### **O2. Разрешения — Уведомления (Explainer) (Apple Human Interface Guidelines+ 2025\)**

* Текст: “Напоминания помогут не пропускать поливы и фиксировать план.”  
* CTA: “Разрешить уведомления”  
* Secondary: “Позже”  
* Если “Позже”: напоминания отключены, но при попытке включить шаблон будет повторный запрос.

### **O3. Создать хозяйство/рабочее пространство (локально) (Apple Human Interface Guidelines+ 2025\)**

* Поля:  
  * “Название” (например “Ферма”)  
  * “Тип полива по умолчанию”: капля/дождевание/смешанный  
* Переключатель:  
  * “Полевой режим (крупные элементы)” — ON по умолчанию для пользователей “в поле”.

### **O4. Добавить первый участок (Plot) (Apple Human Interface Guidelines+ 2025\)**

* Поля:  
  * Название участка (обяз.)  
  * Тип полива (капля/дождевание)  
  * Культура (опционально)  
  * Примечание (опционально)  
* CTA: “Добавить ещё” / “Продолжить”  
* Подсказка: “Можно добавить позже в Участки”.

### **O5. Выбрать пресеты длительности (Apple Human Interface Guidelines+ 2025\)**

* Экран выбора “быстрых кнопок длительности”:  
  * 10, 20, 30, 45, 60 (по умолчанию)  
* Пояснение: “Чтобы фиксировать полив за секунды.”  
* CTA: “Готово”

### **O6. Создать шаблон напоминаний (Apple Human Interface Guidelines+ 2025\)**

* Варианты:  
  1. “Каждые N дней” (например 2 дня)  
  2. “По дням недели” (Пн/Ср/Пт)  
  3. “По фазе” (упрощённый пресет: “активный рост / жаркий период / поддержание” → меняет частоту)  
* Привязка шаблона к участкам (multi-select).  
* CTA: “Включить”

### **O7. Мини-обучение “Как фиксировать полив и состояние” (Apple Human Interface Guidelines+ 2025\)**

* 3 страницы:  
  1. “Календарь → \+ Полив”  
  2. “Фото состояния → оценка → заметка”  
  3. “Сводка недели: частота и пропуски”  
* CTA: “В приложение”

## **3.3 Вкладка “Календарь” (Apple Human Interface Guidelines+ 2025\)**

### **C1. Calendar Home (месяц/неделя/день) (Apple Human Interface Guidelines+ 2025\)**

* Верх:  
  * переключатель вида: **Месяц / Неделя / День**  
  * кнопка “Сегодня”  
  * кнопка “+” (добавить полив/состояние/пропуск)  
* Основная область:  
  * **Месяц:** точки-маркеры под датами (не цветом, а формой: ● факт, ◌ план, — пропуск)  
  * **Неделя:** вертикальные “дорожки” по дням с карточками событий  
  * **День:** таймлайн дня (утро/день/вечер) \+ события  
* Фильтр сверху (chip): “Все участки” → выбор конкретного участка.

**Карточка события полива (Water Event Card) (Apple Human Interface Guidelines+ 2025):**

* крупно: длительность (например “30 мин”)  
* ниже: участок  
* маленько: комментарий (1–2 строки)  
* бейдж типа полива: капля/дождевание (иконка)  
* метка: факт/план/пропуск (иконка \+ подпись)

### **C2. Add Event (sheet) (Apple Human Interface Guidelines+ 2025\)**

Открывается по “+” или из дня.

* Сегмент сверху: **Полив / Состояние / Пропуск**  
* Общие поля:  
  * Дата/время (по умолчанию сейчас)  
  * Участок (последний выбранный — по умолчанию)  
  * Комментарий (короткий)  
* Для “Полив”:  
  * Длительность: быстрые кнопки \+ ручной ввод  
  * Тип полива (капля/дождевание) — подставляется из участка  
  * Флаг “По плану” (если событие создано как план)  
* Для “Состояние”:  
  * Фото (с камеры/галереи)  
  * Оценка: “Сухо / Норма / Влажно / Перелив” (не цветом, а словами \+ иконкой)

# **4\) Логика работы (без аккаунта разработчика) (Apple Human Interface Guidelines+ 2025\)**

## **4.1 Оффлайн-first и хранение данных (Apple Human Interface Guidelines+ 2025\)**

* Все данные локально: участки, события поливов, фото состояния, шаблоны, напоминания.  
* Фото храним в файловой системе, в базе — ссылки и метаданные.  
* Никаких аккаунтов, синхронизаций, облака.

## **4.2 Событийная модель: “План / Факт / Пропуск” (Apple Human Interface Guidelines+ 2025\)**

Событие дня может быть трёх типов:

1. **Факт полива** — то, что реально сделали (длительность, участок, комментарий).  
2. **План полива** — запланированное событие (создано шаблоном или вручную).  
3. **Пропуск** — сознательное “не сделали” с причиной, чтобы аналитика была честной.

**Правила (Apple Human Interface Guidelines+ 2025):**

* План не должен “мешать”: если пользователь записал факт, план на тот же слот может:  
  * автоматически пометиться как “выполнен фактом” (связь), либо  
  * предложить объединить (sheet “Связать факт с планом?”).  
* Пропуск привязывается к плану, если он был, чтобы отчёты не искажались.

## **4.3 Напоминания “по графику и условиям” без внешней погоды (Apple Human Interface Guidelines+ 2025\)**

### **4.3.1 Напоминания по графику**

* Шаблон создаёт плановые события и локальные уведомления:  
  * каждые N дней  
  * по дням недели  
  * по пресету “интенсивность сезона” (упрощённая частота)  
* Уведомление содержит быстрые действия:  
  * “Записать полив”  
  * “Отложить”  
  * “Отметить пропуск”

### **4.3.2 Напоминания по “условиям” (локальная логика)**

Так как внешней погоды нет, “условия” считаем из данных приложения:

* **Если нет поливов X дней** по участку → напоминание “Проверьте участок”  
* **Если последние 2 оценки состояния \= ‘Сухо’** → напоминание “Рекомендуется полив/проверка”  
* **Если плановый полив просрочен** → напоминание “Запланированный полив пропущен”  
* **Если отмечен ‘Дождь’ вручную** (как событие “Осадки”) → можно приостанавливать напоминания на N часов/дней

Важно: пользователь всегда видит “почему напомнили” (текстом), чтобы логика была прозрачной.

## **4.4 Фото состояния и связь с поливами (Apple Human Interface Guidelines+ 2025\)**

* Фото состояния всегда привязано к участку и дате.  
* В карточке участка строим связку:  
  * “последний полив” → “последнее фото состояния”  
* В сравнении “до/после” пользователь выбирает два фото в разные даты.

## **4.5 Экспорт и резервное копирование (Apple Human Interface Guidelines+ 2025\)**

* Экспорт отчётов: PDF/CSV через Share Sheet.  
* Бэкап: экспорт локального архива в Files и импорт обратно (без серверов).

# **6\) Модель данных CoreData (основные сущности) (Apple Human Interface Guidelines+ 2025\)**

## **6.1 Стратегия хранения и принципы данных (Apple Human Interface Guidelines+ 2025\)**

* **Apple Human Interface Guidelines+ 2025:** приложение офлайн-first, поэтому **CoreData — single source of truth**, а медиа (фото) — в файловом хранилище.  
* **Apple Human Interface Guidelines+ 2025:** стек CoreData через `NSPersistentContainer` (стандарт Apple, меньше ошибок, проще поддержка). ([Apple Developer](https://developer.apple.com/documentation/coredata/nspersistentcontainer?utm_source=chatgpt.com))  
* **Apple Human Interface Guidelines+ 2025:** `viewContext` — для UI, фоновые контексты — для импорта/экспорта/пересчётов. ([Apple Developer](https://developer.apple.com/documentation/CoreData/NSPersistentContainer/viewContext?utm_source=chatgpt.com))  
* **Apple Human Interface Guidelines+ 2025:** фото не кладём как большие `Binary Data` в CoreData. Храним:  
  * `filePath` (оригинал),  
  * `thumbPath` (превью),  
  * метаданные (размеры, дата, привязка к участку/событию).  
* **Apple Human Interface Guidelines+ 2025:** удаление по умолчанию “бережное” (архивирование), чтобы история недель/участков не ломалась.

## **6.2 Сущности (Core Entities) (Apple Human Interface Guidelines+ 2025\)**

### **6.2.1 Workspace (рабочее пространство)**

**Apple Human Interface Guidelines+ 2025:** нужно, чтобы приложение ощущалось “готовым инструментом”, а не набором экранов.

### **6.2.2 Plot (участок)**

**Apple Human Interface Guidelines+ 2025:** участок — центр всех сценариев, поэтому поля оптимизированы для быстрых карточек и фильтров.

* `id: UUID`  
* `name: String`  
* `irrigationType: Int16` (enum drip/sprinkler)  
* `cropName: String?` (без локализации, просто строка)  
* `notes: String?`  
* `isArchived: Bool`  
* `sortOrder: Int16`

* `events: [WaterEvent]`

* `plans: [PlanTemplateBinding]` (какие шаблоны применены к участку)  
* `weeklyNotes: [WeeklyNote]`

### **6.2.3 WaterEvent (событие воды: факт/план/пропуск/осадки вручную)**

**Apple Human Interface Guidelines+ 2025:** единая сущность “Event” делает календарь простым и последовательным (предсказуемость).

* `id: UUID`  
* `plot: Plot`  
* `kind: Int16` (enum: actualIrrigation / plannedIrrigation / skipped / manualRain)

* `createdAt, updatedAt: Date`  
  **Опциональные поля для “ручной погоды” (без внешних API):**  
* `rainAmountMM: Double?` (можно оставить nil, если не нужно)  
* `temperatureTag: Int16?` (enum: cool/normal/hot — строго опционально)  
  **Связи:**  
* `attachments: [AttachmentPhoto]` (если прикладываем фото к событию)

### **6.2.4 SoilSnapshot (фото состояния почвы/растений)**

**Apple Human Interface Guidelines+ 2025:** “состояние” — второй главный сигнал, поэтому отдельная сущность, легко строить таймлайн и сравнение.

* `id: UUID`

* `capturedAt: Date`  
* `rating: Int16` (enum: dry/normal/moist/overwatered)

* `createdAt, updatedAt: Date`

* `photo: AttachmentPhoto` (1..1) или `[AttachmentPhoto]` (если допускаем несколько фото за раз)

### **6.2.5 AttachmentPhoto (универсальное фото-вложение)**

**Apple Human Interface Guidelines+ 2025:** единый контракт для фото позволяет одинаково вести галерею и отчёт.

* `id: UUID`  
* `ownerType: Int16` (enum: soilSnapshot/waterEvent)  
* `ownerId: UUID`  
* `filePath: String`  
* `thumbPath: String`  
* `width: Int32`  
* `height: Int32`  
* `caption: String?`  
* `createdAt: Date`  
* `annotationData: Data?` (простая разметка, если включим)

### **6.2.6 SkipReason (справочник причин пропуска)**

**Apple Human Interface Guidelines+ 2025:** для честной аналитики (и чтобы пользователь не печатал одно и то же).

# **7\) Контракты графиков и визуализаций (Pie/Donut, Bar/Timeline) (Apple Human Interface Guidelines+ 2025\)**

## **7.1 Общий принцип визуализаций (Apple Human Interface Guidelines+ 2025\)**

* **Apple Human Interface Guidelines+ 2025:** графики должны быть читаемыми, интерактивными, и **не полагаться только на цвет**. Мы используем монохромные различия: толщина, штриховка, яркость, подписи, SF Symbols.  
* **Apple Human Interface Guidelines+ 2025:** iOS 15+ — без Swift Charts (он iOS 16+), значит рисуем кастомно (SwiftUI `Canvas`/`Path` или CoreAnimation). При этом контракт данных фиксируем единым образом.

## **7.2 Единый контракт данных для графиков (Apple Human Interface Guidelines+ 2025\)**

### **7.2.1 ChartQuery (вход)**

* `scope`: `.workspace` | `.plot(UUID)`  
* `period`: `DateInterval`  
* `filters`:  
  * `eventKinds: [WaterEventKind]?` (actual/planned/skipped/manualRain)  
  * `ratings: [SoilRating]?` (dry/normal/moist/over)  
  * `includeArchivedPlots: Bool`

### **7.2.2 ChartModel (выход)**

* `title: String`  
* `subtitle: String?` (например “Неделя 12–18”)  
* `primaryMetricText: String` (например “4 полива”)  
* `legend: [LegendItem]`  
* `series: [ChartSeries]`  
* `emptyState`: `{title, message, ctaTitle?}`

### **7.2.3 LegendItem**

* `id: String`  
* `label: String`  
* `valueText: String`  
* `sfSymbolName: String`  
* `styleToken: String` (например “fillStrong”, “fillLight”, “hatched”, “outline”)

### **7.2.4 Интерактив (единый стандарт)**

* Tap по элементу графика → highlight \+ “карточка детали” (нижняя панель).  
* Long press → фиксирует выбор \+ haptic.  
* Tap по пустому месту → сброс выбора.

## **7.3 Donut/Pie — “Состояние почвы за неделю” (Apple Human Interface Guidelines+ 2025\)**

**Цель:** понять, какая оценка доминирует и не уходим ли в сухость/перелив.

**DonutSeries:**

* сегменты: `dry`, `normal`, `moist`, `overwatered`  
* данные сегмента:  
  * `count: Int`  
  * `percent: Double`  
  * `labelShort: String` (“Сухо”, “Норма”…)  
  * `sfSymbolName`: (например `drop`, `leaf`, `humidity`, `exclamationmark.triangle` — строго монохром)  
  * `styleToken`: разные оттенки серого \+ штриховка для 1–2 сегментов

**Center label:**

* строка 1: “Снимков”  
* строка 2: “12”  
* строка 3: “за неделю”

**Drill-down (Apple Human Interface Guidelines+ 2025):**

* Tap по сегменту “Сухо” → открывает список снимков (State Gallery) с фильтром rating=dry и period=week.

## **7.4 Donut — “План vs Факт vs Пропуск” (Apple Human Interface Guidelines+ 2025\)**

**Цель:** оценить дисциплину и причины пропусков.

Сегменты:

* Planned (плановые)  
* Actual (фактические)  
* Skipped (пропуски)

Особенность:

* “Planned” и “Actual” различаем не цветом, а:  
  * planned \= outline/штриховка  
  * actual \= заливка  
  * skipped \= контур \+ крестик (иконка в легенде)

Drill-down:

* Tap по “Skipped” → список пропусков с группировкой по причинам (SkipReason).

## **7.5 Bar — “Частота поливов по дням недели” (Apple Human Interface Guidelines+ 2025\)**

**Где:** вкладка “Сводка”, Plot Weekly Detail.

**BarModel:**

* `bins: [DayBin]` для Пн–Вс  
* `DayBin`:  
  * `label: String` (“Пн”)  
  * `actualCount: Int`  
  * `totalDurationMin: Int`  
  * `plannedCount: Int` (опционально вторым слоем)

Отрисовка:

* actual \= основной бар  
* planned \= тонкий “маркер-план” (линия/оверлей)  
* подписи сверху (“3”)

Интерактив:

* Tap на “Ср” → открывает Day Detail (календарь день) с фильтром участков и датой.

## **7.6 Bar — “Тренд по неделям” (Apple Human Interface Guidelines+ 2025\)**

**Цель:** увидеть стабильность поливов.

**Series:**

* по неделям (последние 8–12):  
  * `actualCount`  
  * `skippedCount` (может быть тонкой полосой сверху)  
  * `avgGapDays` (опциональный текст-метрика на карточке)

Интерактив:

* Tap неделя → открывает Weekly Summary на выбранную неделю.

## **7.7 Timeline — “День участка: поливы \+ состояние” (Apple Human Interface Guidelines+ 2025\)**

**Где:** Day Detail, Plot Detail (“Сегодня”).

* `time: Date`  
* `type: event/snapshot`

Поведение:

# **8\) Архитектура (только: стек и слои, протоколы репозиториев, use cases, viewmodels) (Apple Human Interface Guidelines+ 2025\)**

## **8.1 Стек и слои (Apple Human Interface Guidelines+ 2025\)**

**Apple Human Interface Guidelines+ 2025:** нативность и предсказуемость достигаются системными фреймворками и чистым разделением ответственности.

### **8.1.1 Технологический стек (Apple Human Interface Guidelines+ 2025\)**

* **UI:** SwiftUI (экранная логика, состояния, анимации)  
* **UIKit bridges (iOS 15):**  
  * камера/галерея (если нужно) через системные контролы  
  * PDF preview (PDFKit) \+ Share Sheet  
* **Persistence:** CoreData (`NSPersistentContainer`). ([Apple Developer](https://developer.apple.com/documentation/coredata/nspersistentcontainer?utm_source=chatgpt.com))  
* **Notifications:** `UNUserNotificationCenter` (локальные уведомления, действия). ([Apple Developer](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter?utm_source=chatgpt.com))  
* **Background refresh (опционально, без гарантии):** `BGAppRefreshTask` для “обновить расписанные уведомления/сводку”, плюс обязательное обновление при запуске приложения. ([Apple Developer](https://developer.apple.com/documentation/backgroundtasks/bgapprefreshtask?utm_source=chatgpt.com))  
* **PDF генерация:** `UIGraphicsPDFRenderer` (нативно, быстро, без сторонних). ([Apple Developer](https://developer.apple.com/documentation/uikit/uigraphicspdfrenderer?utm_source=chatgpt.com))

### **8.1.2 Слои (Apple Human Interface Guidelines+ 2025\)**

1. **Presentation**: SwiftUI Views \+ ViewModels (MVVM)  
2. **Domain**: Use Cases \+ доменные модели/правила (план/факт/пропуск, условия напоминаний)  
3. **Data**: Repositories (CoreData \+ FileStorage)  
4. **Infrastructure**: NotificationScheduler, BackgroundRefresh, PDFExporter, Permissions

## **8.3 Use Cases (примеры) (Apple Human Interface Guidelines+ 2025\)**

### **8.3.1 Apple Human Interface Guidelines+ 2025 — QuickLogIrrigationUseCase**

**Цель:** записать факт полива за 1 экран.

* Вход: `plotId`, `durationMin`, `comment?`, `time=now`, `irrigationTypeSnapshot`  
* Шаги:  
  1. create `WaterEvent(kind=.actualIrrigation)`  
  2. если в этот день есть ближайший плановый event по участку → предложить связать (не автоматически без ясности)  
  3. триггер пересчёта WeeklyAggregate (фон)  
* Выход: `eventId`

### **8.3.2 Apple Human Interface Guidelines+ 2025 — CreateSoilSnapshotUseCase**

* Вход: `plotId`, `photoData`, `rating`, `tags[]`, `note?`, `capturedAt`  
* Шаги:  
  1. сохранить фото через AttachmentRepository  
  2. создать SoilSnapshot \+ AttachmentPhoto  
  3. если `rating == .dry` и включено правило “drySnapshotsInRow” → поставить флаг для возможного напоминания  
* Выход: `snapshotId`

### **8.3.3 Apple Human Interface Guidelines+ 2025 — GeneratePlanEventsUseCase**

**Цель:** из шаблонов на ближайшие N дней сделать плановые события и уведомления.

* Вход: `daysAhead` (например 14\)  
* Шаги:  
  1. получить активные binding’и шаблонов  
  2. сгенерировать “плановые” WaterEvent(kind=.plannedIrrigation) на период (без дублей)  
  3. расписать локальные уведомления (NotificationScheduler) и сохранить `NotificationTicket`  
* Выход: количество созданных планов и уведомлений

### **8.3.4 Apple Human Interface Guidelines+ 2025 — EvaluateConditionRemindersUseCase**

**Цель:** реализовать “погодные условия” без внешней погоды.

* Правила (локально):  
  * `noIrrigationForDays`: по последнему actualIrrigation  
  * `drySnapshotsInRow`: по последним SoilSnapshot.rating  
  * `plannedMissed`: плановый event в прошлом без связанного факта и без пропуска  
  * `manualRainPause`: если был WaterEvent(kind=.manualRain) недавно — пауза  
* Результат: список “кандидатов” уведомлений (plotId \+ reasonText \+ suggestedAction)

### **8.3.5 Apple Human Interface Guidelines+ 2025 — MarkSkipUseCase**

* Вход: `planEventId` (или дата), `reasonId`, `comment?`  
* Шаги:  
  1. создать WaterEvent(kind=.skipped) и связать с планом  
  2. пересчитать weekly  
  3. отменить/обновить уведомления по плану

### **8.3.6 Apple Human Interface Guidelines+ 2025 — BuildWeeklyReportUseCase**

* Вход: `weekStart`, `plotId?`, `format=pdf/csv`  
* Шаги:  
  1. собрать события и снимки  
  2. построить сводку (counts, durations, распределения rating)  
  3. PDF через `UIGraphicsPDFRenderer` ([Apple Developer](https://developer.apple.com/documentation/uikit/uigraphicspdfrenderer?utm_source=chatgpt.com))  
* Выход: `URL` для Share Sheet

## **8.5 NotificationScheduler (инфраструктура) (Apple Human Interface Guidelines+ 2025\)**

* **Apple Human Interface Guidelines+ 2025:** уведомления — системные, с понятной причиной “почему пришло”.  
* Реализация:  
  * плановые: заранее на 7–14 дней (обновляем при запуске/раз в сутки)  
  * условные: пересчитываем при значимых событиях (новый полив, новый snapshot “сухо”, пропуск, ручной дождь)  
* API:  
  * `UNUserNotificationCenter.add(...)` для постановки ([Apple Developer](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/add%28_%3Awithcompletionhandler%3A%29?utm_source=chatgpt.com))  
  * `getPendingNotificationRequests` для очистки дублей и контроля ([Apple Developer](https://developer.apple.com/documentation/usernotifications/unusernotificationcenter/getpendingnotificationrequests%28completionhandler%3A%29?utm_source=chatgpt.com))
